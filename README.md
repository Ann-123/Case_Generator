# 🧪 QA Test Case Generator

**Микро-SaaS приложение (MVP) для автоматической генерации тест-кейсов и чек-листов на основе текстового описания и визуального анализа страниц через LLM (Mistral).  
Включает в себя:

- **Генератор тест-кейсов** с поддержкой:
  - динамических полей (настраиваемый шаблон);
  - подстановки описаний страниц через плейсхолдеры `{{Имя страницы}}`;
  - **встроенного чек-листа** (позитивные / негативные проверки) – можно выбрать нужные пункты и сгенерировать кейсы только по ним.
- **Библиотека страниц** – загрузка скриншотов UI, их описание через Vision LLM (Pixtral) и сохранение в БД для дальнейшего использования.

---

## ✨ Возможности

- **Конструктор шаблона** – добавляйте/удаляйте любые поля тест-кейса (название, предусловия, шаги, ожидаемый результат, окружение и т.д.)
- **Генерация через LLM** – поддерживается несколько провайдеров (OpenAI, Mistral, Groq, OpenRouter, Ollama)
- **Библиотека страниц** – загрузка скриншотов, автоматическое описание страницы через мультимодальную модель (Mistral Pixtral / LLaVA) и сохранение в SQLite
- **Плейсхолдеры в описании задачи** – пишите `{{Имя страницы}}` в поле задачи, и система подставит сохранённое описание
- **Строгая валидация ответа** – динамическая Pydantic-схема гарантирует, что модель вернёт данные только с указанными атрибутами
- **Копирование в буфер** – результат отображается в структурированном виде и может быть скопирован как JSON
- **Лёгкий фронтенд** – один HTML-файл с Tailwind CSS и ванильным JS (без фреймворков)
- **Готовность к деплою** – FastAPI отдаёт и бэкенд, и статику
- **Интерактивный чек-лист проверок** - автоматическая генерация структурированного списка проверок (позитивные/негативные & функциональные/нефункциональные) с возможностью выбора нужных пунктов перед генерацией тест-кейсов
- **Выборочная генерация** - каждый пункт чек-листа превращается в 1+ детализированных тест-кейсов с автоматическим проставлением типа и категории проверки
- **Проекты и ЧТЗ** - создание проектов, загрузка ТЗ (текст или `.docx`), автоматическое извлечение иерархии требований (ЧТЗ) с помощью LLM
- **Требования и чек-листы** - дерево ФТ, генерация чек-листов для каждого требования, ручное редактирование и удаление
- **Тест-кейсы** - генерация тест-кейсов по пунктам чек-листа, флаг `include_in_pmi` для включения в ПМИ, покрытие требований
- **Шаблоны документов** - загрузка `.docx`-шаблонов для проекта (ПМИ, ПЗ и т.д.) с уникальным `doc_type`
- **Сборка документов** - автоматическая подстановка в шаблоны таблиц ФТ, тест-кейсов ПМИ, матрицы покрытия, списка страниц и требований; редактирование секций и выгрузка готового `.docx`

## 🖥️ Использование

**Вкладка «Генератор» (единый мастер-процесс)**

1. Настройте поля тест-кейса – по умолчанию: «Название», «Предусловия», «Шаги», «Ожидаемый результат». Можно добавлять свои поля (кнопка «+ Добавить поле»).

2. Введите описание задачи – можно использовать плейсхолдеры вида {{Имя страницы}}.
Список доступных страниц отображается под полем ввода – клик по кнопке «Вставить» подставит плейсхолдер в текст.

3. Сформируйте чек-лист (опционально) – нажмите кнопку «Сформировать чек-лист».
Появится блок с пунктами проверок, сгруппированными по областям и разделёнными на позитивные и негативные.

4. Выберите нужные пункты – можно выделить отдельные чекбоксы, целые области или колонки (галочка над колонкой).
Если ничего не выбрать – генерация тест-кейсов пройдёт без привязки к чек-листу.

5. Нажмите «Сгенерировать тест-кейсы» – результат появится в блоке «Результат».
Если были выбраны пункты чек-листа, в запрос автоматически добавится поле «Тип» (Позитивный/Негативный), и кейсы будут сгенерированы только по выбранным проверкам.

6. Скопируйте результат – кнопка «Скопировать всё в буфер» сохраняет JSON с тест-кейсами.

**Вкладка «Проекты»**

1. Создайте проект – укажите название.
2. Загрузите ТЗ проекта:
   - Текстовое описание или файл `.docx` (текст и изображения извлекаются автоматически).
   - Эндпоинт: `POST /projects/{project_id}/upload-tz`.
3. Сгенерируйте ЧТЗ – нажмите кнопку генерации или вызовите `POST /projects/{project_id}/generate-chtz`. LLM разобьёт ТЗ на разделы и функциональные требования (ФТ), которые сохранятся в БД.
4. Просмотрите дерево требований: `GET /projects/{project_id}/requirements-tree`.

**Вкладка «Библиотека страниц»**

1. Загрузка новой страницы:
   - Выберите изображение (скриншот) и введите уникальное имя.
   - Нажмите «Загрузить и распознать» – изображение отправится в Vision LLM, описание страницы сохранится в БД, а само изображение будет сжато и сохранено в `backend/static/uploads/`.

2. Список сохранённых страниц – отображается ниже. Каждую страницу можно удалить (крестик справа).

**Вкладка «Документы»**

1. Загрузите шаблон `.docx` для проекта (`POST /projects/{project_id}/templates`) с указанием типа документа, например `ПМИ` или `ПЗ`.
2. Вставьте в шаблон плейсхолдеры:
   - `{{FT_TABLE}}` — таблица функциональных требований;
   - `{{TEST_CASES}}` — таблица тест-кейсов, включённых в ПМИ;
   - `{{PAGES_DESCRIPTIONS}}` — список описаний страниц;
   - `{{REQUIREMENTS_LIST}}` — нумерованный список требований;
   - `{{COVERAGE_MATRIX}}` — матрица покрытия ФТ чек-листами и тест-кейсами.
3. Соберите документ: `POST /projects/{project_id}/documents/{doc_type}/assemble`. Система вернёт JSON-секции и путь к собранному `.docx`.
4. При необходимости отредактируйте секции: `PUT /projects/{project_id}/documents/{doc_type}/sections/{section_index}`.
5. Выгрузите готовый документ: `GET /projects/{project_id}/documents/{doc_type}/export`.

## 🧱 Архитектура

```
qa-case-generator/  
├── backend/  
│   ├── __init__.py
│   ├── main.py           # FastAPI приложение (эндпоинты, статика, подстановка плейсхолдеров)
│   ├── auth.py           # Проверка X-API-Key
│   ├── database.py       # SQLite: страницы, проекты, требования, чек-листы, тест-кейсы, шаблоны
│   ├── pages.py          # Роутер загрузки/списка/удаления скриншотов
│   ├── projects.py       # Роутер проектов, загрузка ТЗ и генерация ЧТЗ
│   ├── checklists.py     # Роутер чек-листов и тест-кейсов
│   ├── templates.py      # Роутер шаблонов документов
│   ├── documents.py      # Роутер сборки и экспорта документов
│   └── static/  
│       ├── index.html    # Фронтенд (HTML + Tailwind CDN + встроенный JS)
│       └── uploads/      # Сохранённые скриншоты, шаблоны и собранные документы
├── tests/                # Pytest-тесты
├── requirements.txt  
├── .env                  # API-ключи и конфигурация (не коммитить!)
└── README.md  
```

## 🛠 Технологии

- **Backend**: Python 3.10+, FastAPI, Pydantic, SQLite3
- **Frontend**: HTML5, Tailwind CSS (CDN), Vanilla JS
- **LLM**: Mistral API (текстовые модели + Pixtral для зрения)
- **База данных**: SQLite
- **Работа с документами**: `python-docx` для загрузки, сборки и выгрузки `.docx`
- **Оптимизации**:
  - батчинг запросов к БД для плейсхолдеров (устранение N+1);
  - кэширование описаний страниц в памяти;
  - сжатие изображений перед отправкой в Vision API;
  - унификация парсинга JSON от LLM.

## ⚙️ Быстрый старт

### 1. Клонируйте репозиторий
```bash
git clone https://github.com/Ann-123/Case_Generator.git
cd Case_Generator
```
### 2. Настройте переменные окружения
Создайте файл .env в корне проекта. Пример для Mistral AI:
```
LLM_PROVIDER=mistral
MISTRAL_API_KEY=mistral_ваш_ключ
LLM_MODEL=open-mistral-nemo
VISION_MODEL=pixtral-12b-2409   # модель для распознавания скриншотов
```
### 3. Установите зависимости
```
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```
### 4. Запустите сервер
```
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```
### 5. Откройте приложение
Перейдите на http://localhost:8000

## 📡 API Endpoints

### Генерация
- `POST /generate` — генерация тест-кейсов.
  Тело: `{ "task_text": "...", "fields": ["Название", ...], "checklist_items": [...] }` (последнее — опционально).
- `POST /generate-checklist` — генерация чек-листа.
  Тело: `{ "task_text": "..." }`.

### Аутентификация
- `POST /auth/check` — проверка заголовка `X-API-Key`.

### Библиотека страниц
- `POST /pages/upload` — загрузка страницы (`multipart/form-data`: `file`, `name`).
- `GET /pages/list` — список всех страниц.
- `DELETE /pages/{name}` — удаление страницы.

### Проекты
- `POST /projects` — создать проект.
- `GET /projects` — список проектов.
- `GET /projects/{project_id}/tz` — получить сохранённый текст ТЗ.
- `POST /projects/{project_id}/upload-tz` — загрузить ТЗ (текст или `.docx`).
- `POST /projects/{project_id}/generate-chtz` — сгенерировать ЧТЗ из ТЗ и сохранить в БД.
- `GET /projects/{project_id}/requirements-tree` — дерево требований проекта.

### Чек-листы и тест-кейсы
- `POST /requirements/{requirement_id}/checklist` — сгенерировать чек-лист для требования.
- `GET /checklists/{checklist_id}` — получить чек-лист.
- `PUT /checklists/{checklist_id}` — обновить `items_json` чек-листа.
- `DELETE /checklists/{checklist_id}` — удалить чек-лист.
- `POST /checklists/{checklist_id}/testcase/{item_id}` — сгенерировать тест-кейс по пункту чек-листа.
- `GET /testcases/{testcase_id}` — получить тест-кейс.
- `PUT /testcases/{testcase_id}` — обновить тест-кейс.
- `DELETE /testcases/{testcase_id}` — удалить тест-кейс.
- `GET /requirements/{requirement_id}/coverage` — сводка покрытия требования.

### Шаблоны документов
- `POST /projects/{project_id}/templates` — загрузить `.docx`-шаблон (`doc_type` + `file`).
- `GET /projects/{project_id}/templates` — список шаблонов проекта.
- `DELETE /projects/{project_id}/templates/{doc_type}` — удалить шаблон.

### Сборка и экспорт документов
- `POST /projects/{project_id}/documents/{doc_type}/assemble` — собрать документ по шаблону.
- `GET /projects/{project_id}/documents/{doc_type}/sections` — получить секции собранного документа.
- `PUT /projects/{project_id}/documents/{doc_type}/sections/{section_index}` — изменить текст секции.
- `GET /projects/{project_id}/documents/{doc_type}/export` — выгрузить готовый `.docx`.

Подробные схемы запросов и ответов можно посмотреть в коде соответствующих роутеров (`backend/main.py`, `backend/pages.py`, `backend/projects.py`, `backend/checklists.py`, `backend/templates.py`, `backend/documents.py`).
