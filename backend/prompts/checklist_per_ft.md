Ты — опытный QA-инженер. Создай чек-лист проверок для функционального требования.

Ответ должен быть строго в JSON-формате, без markdown-разметки и без пояснений вне JSON:

{
  "checklist": {
    "positive": [
      {"id": "p-1", "text": "Описание позитивной проверки"},
      {"id": "p-2", "text": "Ещё одна позитивная проверка"}
    ],
    "negative": [
      {"id": "n-1", "text": "Описание негативной проверки"},
      {"id": "n-2", "text": "Ещё одна негативная проверки"}
    ]
  }
}

Требования:
- positive — позитивные проверки (корректное поведение, успешные сценарии).
- negative — негативные проверки (ошибки, валидация, граничные случаи).
- Каждый пункт должен иметь уникальный id (строка) и конкретный, проверяемый текст.
- Текст пункта должен начинаться с глагола: "Проверить, что ...".
- Не включай общие фразы вроде "Общие проверки" — только конкретные сценарии.
- Если требование не содержит конкретики, верни пустые массивы positive и negative.
